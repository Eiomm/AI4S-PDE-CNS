## Latest Notice, 2026-04-24

The page announces an additional preliminary-round problem: **Task 2: multi-physics environment prediction**.

Task 1 is described as prediction under a fixed physical parameter, `Nu=0.001`. Task 2 is introduced to test whether neural operators can generalize across varying viscosity coefficients.

Task 2 requirements and implications:

- Training data provides `Nu` values.
- Participants may decide how to use training-time `Nu`, for example as a conditional input or for data augmentation.
- Test data does not provide `Nu`.
- Test inference must predict from the initial condition only.
- Task 2 training time is not counted directly in the score.
- Total Task 2 exploration/training time must stay within 12 hours.
- Task 2 inference time must be within 2 minutes.

The notice also says the organizers updated:

- GPU time conversion coefficients, including support for V100 and RTX 4090.
- Detailed scoring rules.

## Latest Notice, 2026-05-07

The page adds a log-file format requirement for `task1_logs.log` and `task2_logs.log`, effective immediately.

Required log format:

- Each line must be valid JSON.
- Each JSON record must capture the agent's complete LLM response for an LLM call.
- Each JSON record must include:
  - `timestamp`: ISO 8601 timestamp with timezone for completion of the LLM call.
  - `elapsed_seconds`: elapsed time in seconds for the LLM call.

The organizers provide a local forwarding proxy sample:

```bash
python proxy.py --port 8080 --target https://api.openai.com --log-dir ./logs
```

The agent API base URL can be pointed to `http://localhost:8080` so the proxy forwards requests and writes logs.

Code-log correspondence requirements:

- Submitted `code/` must be fully generated by the agent.
- Submitted `code/` must not contain manually written or manually modified content.
- Code content must correspond to the LLM call history recorded in the logs.
- Logs should make the code-generation process traceable.

Zero-score violation cases listed in the notice:

- Log file does not exist.
- A log line is not valid JSON.
- A JSON line misses `timestamp` or `elapsed_seconds`.
- The time delta between the first and last log records exceeds 12 hours.
- Reviewers determine that submitted code cannot be matched to the log history.

## Race Description Rules Relevant To This Project

The race asks participants to build an LLM-based PDE research agent, not merely submit a manually tuned model. The agent should support:

- Literature and baseline understanding.
- Bottleneck diagnosis and hypothesis formulation.
- Autonomous code evolution.
- Experimental validation and reflection.
- A comprehensive research log.

Evaluation dimensions named in the race description:

- Scientific performance: task metrics such as prediction accuracy and generalization.
- Computational economy: latency, memory, parameter/output efficiency.
- Logical rigor of evolution: transparent reasoning chain from diagnosis to hypothesis to code evolution.

Preliminary round task description:

- Dataset: 1D subset of PDEBench, focused on 1D Burgers.
- Baseline families: FNO, DeepONet, PI-DeepONet.
- Official PDEBench checkpoints may be loaded for Task 1 fine-tuning.
- Physics-informed constraints may be used in training or inference.
- Evaluation emphasizes short-term accurate prediction and medium/long-term stable prediction.

## Submission Requirements From Race Description

The race description lists the preliminary submission materials as:

- `agent_research_log.zip`
  - original dialogue or trace records for literature review, hypothesis generation, and model code modifications.
  - experiment tracking records for all experimental versions.
  - records should include configuration or code versions, modification details, conclusions.
  - must include two comparative experiments and one failed-experiment analysis, not only optimal results.
- `methodology.pdf`
  - brief description of the agent architecture.
  - should state which LLM was used and how the tool-use loop was designed.
- Prediction results:
  - `submission.json`
  - prediction HDF5 file pointed to by `submit_path`, containing dataset `tensor`.
  - timing CSV pointed to by `time_path`, containing `train_time` and `inference_time`.
