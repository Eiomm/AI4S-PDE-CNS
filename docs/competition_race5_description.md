## Task Goal

Build an agent that designs target-specific drug-like small molecules and plans their synthetic routes.

The agent receives one or more protein targets and must, within a time limit, generate molecules plus corresponding synthesis paths. The final evaluation is based on the generated CSV files and the agent execution log.

The official description explicitly allows agents to use:

- LLM APIs
- locally deployed or fine-tuned LLMs
- downloaded local open-source models for molecular generation or retrosynthesis
- self-designed and trained models

The training and fine-tuning process is expected to be handled by the agent rather than manually hard-coded as final fixed outputs.

## Preliminary Round Contract

Input:

- One target protein structure: `target.pdb`

Submission:

- Submit `result.zip`
- The zip must contain:
  - `result.csv`
  - `result.log`

`result.csv` format:

```csv
mol_smiles,route
```

Rules:

- `mol_smiles` is the generated molecule SMILES for the target.
- `route` is the synthesis path for that molecule.
- Multiple reaction steps are separated with commas.
- The product of the final reaction step must be identical to the `mol_smiles` value.
- `result.log` should record the agent execution process.
- The log is used to show that the result was generated by an agent process.



Semifinal constraints:

- Results must be generated by the agent inside the container.
- Results must not already exist in the container.
- Results must not be produced by simple copying or moving.
- Results must not be selected from a pre-supplied fixed molecule or route library packaged in the image.
- The official wording expects visible design, generation, improvement, and evolution steps by the agent.
- Molecule-vs-route weight changes from preliminary `7:3` to semifinal `6:4`.

## Scoring Notes

FAQ molecule scoring:

- Preliminary molecule score weight in the FAQ: `0.7`; semifinal overall ranking uses molecule:route = `6:4`.
- Inside molecule score:
  - `0.8 binding_score`, scored using AutoDock Vina
  - `0.1 validity_score`, binary structural-validity check
  - `0.1 sa_score`, where SAscore greater than 4 gives 0, and lower SAscore is better when SAscore is at most 4

FAQ synthetic-route scoring:

- Preliminary route score weight in the FAQ: `0.3`; semifinal overall ranking uses molecule:route = `6:4`.
- Inside route score:
  - `0.55 route_validity_score`
  - `0.30 starting_material_availability_score`
  - `0.05 step_penalty_score`
  - `0.05 convergence_score`
  - `0.05 balance_score`

Hard-zero rules from the FAQ:

- If molecular `validity_score` is 0, the molecule score becomes 0.
- If the final product of the synthetic route is not the designed molecule, the route score becomes 0.
- If `balance_score` is 0, the route score becomes 0.
- Route score can be 0 even when all route molecules are valid if:
  - the final synthesized product differs from the designed molecule
  - a reaction product contains an element not present in reactants
  - a reaction uses the product molecule as a reactant, effectively preparing `A` from `A`

Semifinal task note:

- The molecule-route overall weight is changed to `6:4`.

## Semifinal CNS Multi-Track Rule

The CNS challenge semifinal asks participants to choose at least 2 of the 4 tasks. Participants may choose 2, 3, or 4 tasks. Fewer than 2 valid task entries means the participant does not meet semifinal review requirements and is excluded from final ranking.

Scores are standardized per task using z-score. A participant's semifinal total score is the sum of the two highest task z-scores.

Final advancement:

- Rank by semifinal total score.
- Top 6 advance to the final.
- Tie breakers listed by the official rule:
  - higher best single-task z-score
  - higher third-task z-score, if available
  - final organizing-committee ruling if still tied

## Code Submission Notes

Preliminary code-review folder structure:

```text
Code/
├── main.py
├── README.md
├── ...
Data/
├── target.pdb
Output/
├── result.zip

├── ...
```

Important code-review requirements:

- Source code used to reproduce results should be included under `Code/`.
- `Code/main.py` is the required entry script.
- `README.md` should describe the agent workflow, dependencies, exact versions, and entry command such as `python -u main.py`.
- API keys should remain placeholders.
- File paths should be relative, for example `../Data/`.
- Add enough comments and README detail for code review.
- `Data/` stores the target file.
- `Output/` stores inference output and the required zip file.
- `Reference/` can store planning references used by the agent.

## Implications For This Repo

Current project guardrails derived from the official page:

- Keep `result.csv`/`result.log`/`result.zip` compatible for single-target local runs.
- For semifinal mode, add or preserve support for three targets and write `result1.csv`, `result2.csv`, `result3.csv` into `/saisresult/result.zip`.
- Always ensure route final product equals `mol_smiles`.
- Avoid fake fixed-output behavior; logs should show planner decisions, tool calls, evaluation, memory, and iteration.
- Prefer real AutoDock Vina integration for molecule ranking because binding score dominates molecule scoring.
- Improve route generation and validation because semifinal weighting increases route importance to 40%.
- Check reaction balance and element coverage; route-valid molecules alone are not enough.
- Keep training and inference code reproducible for manual review.
